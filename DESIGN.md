# Visual design reference

This document describes the existing interface, not a redesign or task board. Source of truth: `apps/desktop/src/styles.css`, `apps/desktop/src/App.tsx` and `apps/desktop/src/features/live/`. Product boundaries remain in [architecture](docs/architecture.md); acceptance evidence remains in [Live Mode](docs/live-mode.md).

## Purpose and hierarchy

- Prioritize readable interview assistance over decorative dashboard elements. Live is the primary workspace; Knowledge Base and basic Practice remain available in the navigation.
- Keep session state, provider and capture actions in one compact header. Expanded Live uses two columns: transcript left (~35%) and a continuous newest-first Q&A queue right (~65%), excluding the gap. Keep the Q&A panel first in DOM/keyboard order. Compact prioritizes the same queue before transcript.
- Keep transcript and the Q&A queue independently scrollable. There is no separate answer-history section. Each question has one stable card; correlated documentary/AI/failure updates enrich it in place without reordering. Previous cards remain below it. Show new transcript fragments first and update one provisional entry in place. One stable DOM structure serves both modes.
- Transcript is permanently visible with a noninteractive heading in both modes, not a disclosure or toggle. Compact places it after the answer-first queue. Its feed stays mounted in both modes. Q&A has no visible Newest first / Lo más reciente arriba label; ordering remains newest-first.
- Keep manual document lookup and technical diagnostics secondary in native, initially closed disclosures. Consent, provider/language selection and the real Start click stay in the auxiliary window.

## Existing visual language

- Live uses a restrained navy palette: page `#0c111b`, panel `#121a27`, reading surface `#182232`, border `#2b384b`. A small set of `--live-*` CSS variables defines these roles; no component framework is added.
- Primary text is `#e8edf5`; supporting text is `#a7b5c9`. Indigo actions use `#4d5cbb`, with `#5968c7` hover and a light focus outline. Provenance colors decorate labels and thin accents, not whole tinted cards.
- The Live shell has a quieter brand mark, 208 px navigation and a wrapping topbar with a 56 px minimum for the interface-language selector. Other pages retain their established layout and branding; this is not a global dashboard rebuild.
- Keep Segoe UI/system fonts. Expanded Live uses a 24 px heading and 20 px current question; compact uses 18 px for both. Answer text is 17 px (16 px when compact/stacked), transcripts 14 px and supporting copy 12 px. Answer line height is 1.65, with a 68ch maximum measure. No remote fonts or assets.
- Panel gaps are 16 px; reading-card padding is 20 px, reduced to 16 px when stacked. Controls use at least 40 px height; auxiliary actions use 42 px. Keep spacing consistent without turning these few roles into a general design-system abstraction.
- Use the existing Lucide outline icons alongside text. Icons and color do not replace action labels, provenance or warnings.

## Provenance must remain visible

- **Exact documentary answer:** green-accented card, exact-match label and document source. Exact matching is not factual certification.
- **Semantic candidate:** amber treatment, explicit review label, source and stored question when supplied.
- **No evidence:** explicit documentary absence, not a model or STT failure. Correlated generation failures retain their localized reason inside the same question card, without fabricating an answer or changing audio state.
- **Generated suggestion:** a distinct lavender-labeled section within that same question card, with provider/model, no documentary source and an unverified-content warning. Keep the documentary absence label above it; do not create a second card or attribute the AI section to a document.
- Card correlation requires both `session_id` and `question_id`, never repeated wording. Documentary updates and AI/failure events retain the first card key and queue position. Matching late outcomes can update retained older cards without moving them; unmatched/evicted AI cannot create a card. Existing exact/semantic sources remain explicit; a documentary found result excludes AI enrichment.
- The first card appears on the existing documentary event: there is no separate detection/RAG-start event. Until an explicit AI result/failure, say that no AI suggestion has been received and generation start is unconfirmed, not Generating or Completed. New questions mark unresolved older cards superseded. Stop/error/restart retain cards and failure reasons but close incomplete outcomes to obsolete AI. These are presentation lifecycle states, not new provider cancellation acknowledgements.
- **Interim transcript:** dashed blue container with a static, subtle listening dot and localized listening text; the accessible group name identifies it as interim. Finalized entries have quiet dividers and no visible Final badge. A visually hidden EN/ES prefix identifies finalized text. Keep internal final/interim states, newest-first order and replay deduplication unchanged. Render supplied text as text, never HTML.

## Controls and states

- Keep one primary capture-preparation/show-controls action and a secondary stop-and-close action. Disable unavailable/busy actions instead of implying capture started.
- The pin control shows localized On/Off text, a Pin/PinOff icon and distinct border/background treatment. `aria-pressed` reflects confirmed native state, not an optimistic toggle. During a request it keeps the last confirmation and shows Updating; failed confirmation shows Unconfirmed without asserting pressed=false. Read native state before toggling, block overlapping clicks, and allow retry using the existing bridge.
- Distinguish authorization, connecting, listening, stopping, stopped and error states. Leave provider/audio state unconfirmed when the existing events do not establish it; distinguish local from cloud STT.
- Keep keyboard-focus outlines on controls, disclosure summaries and scroll regions. Navigation has explicit accessible names and current-page state even when labels are hidden. Status/error text uses semantic roles; do not rely on colored dots alone.
- Announce the latest final transcript through a dedicated polite status region outside the transcript panel, not every interim change or the complete history. This region remains mounted in both modes. Duplicate auxiliary feeds do not continuously announce updates. Actual assistive-technology behavior needs Windows validation.
- The topbar exposes a labeled EN/ES interface selector. Switching updates authored labels, known states/warnings and accessible names without reloading or remounting the workspace. Only the interface preference persists in the main renderer; STT/LLM language and supplied interview/document content remain unchanged. At narrow widths the selector label stays available to assistive technology while visually hidden.
- Privacy copy states that system capture includes all Windows output. Main-window protection is requested/best-effort, not guaranteed invisibility; the auxiliary window is not protected.
- Deepgram Settings distinguishes the Windows-stored key, effective backend source for new sessions and remote verification (not performed). Local configuration never establishes remote authentication. Keep localized operation outcomes beside the actions, separate from status-refresh failures; a failed refresh cannot erase a confirmed save, replacement or deletion. Timeout/unknown outcomes require refresh before retrying. Deleting the Windows key neither removes the environment override nor revokes the provider key; the override still takes priority until removed from the startup environment and the backend restarted. Entry remains native, never a renderer credential field.
- Important notices reuse the bordered, tinted availability banner with four severity colors: amber warnings (including missing credentials/runtime), red errors (including invalid configuration and failed checks), blue information (including unknown/loading), and green confirmed success/local readiness. Keep cause-specific decorative SVG icons, concise localized titles and recovery copy; color alone never conveys meaning. Green never certifies remote authentication or external authorization. Existing Refresh/Open Settings actions and separate credential-operation outcomes remain; loading, completion, no-change, failure and automatic refresh stay visible.
- Live preflight/error notices and the isolated capture authorization reminder remain outside disclosures without dismiss controls. The note-taking reminder cannot verify participant/interview authorization and remains visible in capture controls even after in-app audio consent. The existing checkbox retains local/cloud wording and resets on provider changes; reviewing it only focuses the checkbox, never grants permission or starts capture. Known browser capture denials/cancellations explain Windows/organization restrictions without diagnosing provider authentication. Important errors in the main workspace use atomic alert announcements; capture/availability updates use polite atomic status regions. Keep wrapping, opaque notice backgrounds, visible keyboard focus and the existing capture-window Start click. Minimum windows may require vertical scrolling; no animations or new notification framework are introduced.
- Compact/expanded switches reuse the same main window and mounted Live workspace. Keep mode, background opacity and per-mode window rectangles in memory only. Preserve pin state, capture controls, EN/ES and tray recovery.
- On Windows, transparent-capable startup uses custom drag/minimize/close chrome. Start opaque; compact background alpha is adjustable from 0.8 to 1 in **Overlay appearance**, directly below the header in both modes. Label the saved setting **Compact-mode opacity**; expanded always remains opaque. Never apply opacity to the whole window or text. Manual resize is disabled only while translucent; explain **Opaque background** before resizing. Native failures fall back to opaque; `COPILOT_OPAQUE_WINDOW=1` starts with a normal opaque native frame.

## Responsive behavior and limits

- Expanded Live uses an icon rail at 1100 px window width and below, preserving the two-column reading area at the 880 × 650 px native minimum. At 720 px usable content width or below, stack answers first. Compact hides navigation and starts at 520 × 700 px, with a 420 × 400 px minimum. Mode restoration clamps rectangles/minimums to the display work area and restores expanded maximization. No persistent layout settings.
- Compact uses aligned two-column control rows and a sticky, opaque command header below the topbar. Its bounded results grid reserves two independently scrolling rows, Q&A first and transcript second; the transcript row has a 140 px minimum including its heading. At heights ≤520 px, the duplicate Live heading/current-panel heading become visually hidden, the redundant listening-ready line is omitted, and appearance/no-evidence spacing tightens. State, provider, pin, capture/Stop and provenance stay available. Answer text remains 16 px; no fit-to-window shrinking. Minimum height still needs vertical page/feed scrolling.
- Expanded reading-region height is viewport-bounded. The transcript uses a flex column with a fixed heading and a bounded, independently scrolling feed; no native disclosure-content wrapper is involved. The Q&A queue uses one scroll region; new outcomes do not create separate reading panels or force scroll-to-top.
- Native scroll anchoring is enabled for prepended histories; the changing provisional row is not an anchor. No focus jumps or forced scroll-to-top are introduced. Stability while reading older entries still requires a rendered Windows check.
- Histories are bounded and memory-only: up to 80 finalized transcript fragments and 20 question cards, each containing at most one documentary result and one correlated AI suggestion. Native replay remains separately bounded and may restore fewer cards. Legacy documentary events without IDs remain independent cards; do not infer identity from wording. Do not present retained answers as a durable archive or an answer to a newer question.
- Existing explicit new-capture initialization can still reset the workspace; the queue does not introduce cross-session persistence. Mode/locale switches do not reset cards.
- Integrated auxiliary controls default to 560 × 720 px, retaining the 490 × 520 px minimum. Provider/language, Deepgram profile when selected, full consent, cloud/sharing warnings, availability, Start/Stop and session status remain outside disclosures. Diagnostics and duplicate feeds start collapsed, with bounded scroll areas when opened. The action/status strip is sticky; it does not auto-start or auto-authorize anything.
- Auxiliary styles are scoped to `.capture-page`; the raw-audio lab keeps its layout. The shared transcription page also remains usable standalone. Hidden diagnostic DOM still updates through the existing capture script; collapsing it does not bound its accumulation or change capture/lifecycle behavior.
- Once backend readiness and the connected, running AudioWorklet path are confirmed, integrated capture hides the auxiliary and skips both taskbar buttons. A native recovery tray must exist first; its click restores the main workspace and its menu exposes controls/stop. Showing controls reuses the same window; an explicit hide-without-stop action is available during active capture. Stop/error restores normal taskbar behavior. Missing PCM progress or a nonrunning audio context restores controls and prevents rehide until a new attempt. These are recovery mechanisms, not invisibility or audio-health guarantees; real Windows acceptance remains pending.
- Focused Impeccable review used the rendered expanded, compact and minimum layouts with synthetic data. At the minimum size vertical scrolling is necessary; no horizontal overflow was observed. Real Windows transparency/composition, drag/resize, display scaling, keyboard/assistive-technology behavior and contrast over actual backgrounds still need owner review. Synthetic renderer checks are not a formal accessibility audit or proof of screen-sharing exclusion.
