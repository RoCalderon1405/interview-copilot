## STT-001B results and agreed product direction

**Observed on Windows (2026-11-16):** Deepgram Nova-3 returned partial and final English transcripts in the Electron capture window and relayed finals/questions to React. The owner observed a small but unmeasured delay. The detector incorrectly treated some spoken test instructions as interview questions. This is **partial acceptance**, not a latency SLA or validated production release. Spanish, interruptions, restart, network failure and end-to-end latency remain unverified. A `no_evidence` documentary response is not an STT failure.

The following decisions are approved **as product direction**, not permission to implement all tasks at once:

- **Question intent (DET-002, acceptance pending):** an initial conservative implementation accepts implicit interview requests and rejects narrowly recognized operational display checks. The broader goal remains to detect requests such as "Tell me about your experience with React", "Walk me through your architecture" and "Explain dependency injection" without treating ordinary instructions, quoted examples or incomplete phrases as questions. Validate real EN/ES examples, false positives, false negatives, deduplication and abstention. Do not prompt Ollama until an utterance is complete; do not make a large new agent framework.
- **Endpoint-split question assembly (STT-001B, acceptance pending):** Deepgram finalizes per 300 ms endpoint, so a natural pause can split one question. A connection-local, Deepgram-only assembly now holds only clearly incomplete requests or explicit introductions and joins them only with a recognized continuation (subordinate wh clause, narrow noun phrase, an explicit complement after a narrow indirect prompt, or a relative clause after an EN/ES behavioral context tail such as "about a time" / "una vez"); an indirect complement that is itself truncated is held, never evaluated on its own. Complete finals are evaluated immediately with the unchanged detector/dedupe/retrieval/generation path; independent questions, independently punctuated clauses, short prose and unrelated statements are never merged, and an unfinished hold is discarded on stop, error, disconnect or restart without retrieval. Only a behavioral request completed by its relative clause waits for a small connection-owned stabilization window (1 s, capped at 2 s from its start) so its coordinated follow-up ("and what did you change") stays one candidate; that compound is not split by the shared detector, and every other question is unchanged. The deadline is serialized with final processing, never cancelled once it started delivering, drained with the pump and generation on close, and a delivery failure is reported once through the bounded connection error path. Transcripts, their order and timing are unchanged. See [evidence and remaining Windows checks](live-mode.md#stt-001b--deepgram-endpoint-split-candidate-assembly-2026-11-24). This is a lexical heuristic, not semantic detection or perfect isolation.
- **Independent provider selection:** STT: Vosk (local default), Faster-Whisper (optional local), Deepgram Nova-3 (optional cloud); evaluate AssemblyAI later, not as a new automatic fallback. LLM: existing local Ollama plus AI-002's planned selectable cloud BYOK provider (DeepSeek first; OpenAI deferred). The earlier OpenAI-only placeholder is superseded; this does not change completed work. Never conflate the STT choice with the LLM choice or silently switch cloud providers.
- **BYOK/security (CLOUD-001):** implemented Windows development Settings uses native entry and Credential Manager. The backend environment retains priority; invalid overrides do not fall back. No keys in renderer state, IPC, plaintext SQLite, logs, Git or bundled installers. Owner acceptance remains pending; cloud audio still requires separate consent and Vosk remains the default. See setup/architecture for current behavior.
- **Cost estimates and usage (COST-001):** before a paid session, display a price estimate based on the selected STT/LLM provider, model and planned duration, with clear assumptions and current rates. After the session, show measured STT usage (including provider-billable time when obtainable), actual reported LLM token usage when available and **estimated** monetary cost; avoid claiming access to the provider's invoice. Local API charges are zero, not necessarily zero hardware/electricity cost. Prices and free credits vary and must not be hardcoded as permanent facts.
- **Local session history (HIST-001):** opt-in/approved persistence of session metadata, provider/model, durations, usage estimates and costs. Keep audio and full Live transcripts out of persistent history by default. Define deletion, retention and privacy before implementing.
- **Real-time UX (UI-001/MET-001):** show the actual selected STT provider (not "STT local" for cloud); distinguish partial and final text. Measure time-to-first-partial, end-of-speech-to-final and final-to-suggestion separately, plus p50/p95 in repeatable real Windows tests. Optimize only after measurements.
- **Validation and release:** run EN/ES human speech, realistic Teams/Meet/Zoom system audio, network disconnect/stop/restart, Vosk and Whisper regressions, API/browser security and main-window behavior before closing STT-001B. The app is Windows development-mode only; screen-capture exclusion is best-effort and still unverified in meetings.

The existing exact Q&A > optional semantic candidate > explicit no-documentary-evidence policy stays unchanged. Local Ollama suggestions are separate, clearly marked unverified and opt-in. Future cloud LLM output must follow the same provenance rules, with explicit provider selection and disclosure before transmission. `AGENTS.md` remains short and limited to permanent engineering rules.
